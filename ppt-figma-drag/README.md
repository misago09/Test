# PPT Figma Drag

파워포인트의 마우스 조작을 **피그마처럼** 바꿔주는 윈도우 트레이 프로그램입니다.

| 조작 | 파워포인트 기본 | 이 프로그램 실행 후 |
|---|---|---|
| 빈 캔버스 드래그 | 완전히 **포함된** 도형만 선택 | **걸치기만 해도** 선택 (피그마 방식) |
| 가운데 버튼 드래그 | 없음 | **뷰포트 이동(팬)** — 커서에 화면이 자석처럼 밀착 |
| 휠 스크롤 | 줄 단위 스크롤, 끝에서 **다음 슬라이드로 넘어감** | 부드러운 이동, **슬라이드 안에서만** (넘김 방지) |
| Shift+휠 / 틸트 휠 | (세로/불규칙) | 가로 이동 |
| Ctrl+휠 | 화면 중앙 기준 확대/축소 | **마우스 커서 기준** 확대/축소 (피그마 방식) |

AutoHotkey를 쓰지 않으며, 별도 런타임 설치도 필요 없습니다 (.NET Framework 4.8 —
Windows 10/11에 기본 내장).

## 왜 안 버벅거리나

흔한 트레이 앱 구현(특히 Python 계열)은 전역 마우스 훅 콜백 안에서 COM 호출이나
그리기 같은 무거운 작업을 해서 **시스템 전체 마우스가 밀리는** 렉이 생깁니다.
이 프로그램은 구조적으로 그 문제를 피합니다.

1. **훅 콜백은 사실상 아무 일도 안 함** — 왼쪽 버튼 다운/업 좌표를 큐에 넣는 것이
   전부이고, 마우스 이동 이벤트는 비교 한 번 후 즉시 통과시킵니다. (COM 호출 0회,
   그리기 0회)
2. **러버밴드를 직접 그리지 않음** — 드래그 사각형은 파워포인트가 원래 그리던
   것을 그대로 사용합니다. 마우스 이동을 추적하지 않으므로 드래그 중 추가
   부하가 없습니다.
3. **PowerPoint COM 작업은 전부 별도 워커 스레드에서** — 버튼을 누른 시점에
   도형 배치 스냅샷을, 뗀 시점에 선택 확장을 처리합니다. 마우스 입력 경로와
   완전히 분리되어 있어 COM이 느려도 마우스는 밀리지 않습니다.

## 빌드 방법

### 방법 1 — 아무것도 설치하지 않고 (권장)

저장소를 받은 뒤 `ppt-figma-drag` 폴더에서 **`build.cmd`를 더블클릭**하면
윈도우에 내장된 C# 컴파일러로 `PptFigmaDrag.exe`가 만들어집니다.

### 방법 2 — .NET SDK가 있다면

```
cd ppt-figma-drag
dotnet build -c Release
```

## 사용 방법

1. `PptFigmaDrag.exe` 실행 → 작업 표시줄 트레이에 파란 점선 사각형 아이콘이 생깁니다.
2. 파워포인트에서 빈 캔버스를 드래그하면, 사각형에 **걸친 도형까지 전부** 선택됩니다.
   (`Shift`+드래그: 기존 선택에 추가 — 피그마와 동일)
3. **가운데 버튼 드래그**: 뷰포트 이동. **휠**: 부드러운 세로 스크롤,
   **Shift+휠**: 가로 스크롤, **Ctrl+휠**: 커서 기준 확대/축소.
4. 트레이 아이콘 우클릭 메뉴:
   - **걸침 선택** 체크 해제 → 드래그 선택만 파워포인트 기본 동작으로 복귀
     (아이콘 더블클릭으로도 토글)
   - **피그마식 이동/확대** 체크 해제 → 가운데 드래그·휠·Ctrl+휠 개입 중지
   - **뷰포트 진단 로그 기록** → 아래 "뷰포트 진단 로그" 참고
   - **Windows 시작 시 자동 실행** 등록/해제
   - **종료**

## 피그마식 화면 이동/확대의 동작 원리

가운데 드래그·휠·Ctrl+휠은 Windows **터치 주입 API**(`InjectTouchInput`)로
**두 손가락 터치 제스처를 합성**해 구현합니다. 정밀 터치패드의 두 손가락
팬/핀치와 같은 경로(DirectManipulation)로 PowerPoint에 전달되므로:

- 팬이 OS 합성 수준에서 **픽셀 단위 1:1** — 드래그하는 동안 콘텐츠가 커서에
  자석처럼 붙어 움직입니다. (제스처 종료 직전 정지 프레임을 넣어 관성
  스크롤도 발생하지 않습니다)
- Ctrl+휠은 커서를 중심으로 한 핀치를 합성하므로 **커서 위치 기준 확대/축소**가
  파워포인트 네이티브 줌으로 일어납니다.
- 휠 스크롤은 작은 팬 제스처로 변환되며, 현재 슬라이드 경계까지 남은 거리를
  계산해 그 이상은 이동하지 않습니다(경계 클램프; 뷰포트 정보를 못 읽는
  드문 경우에는 클램프 없이 동작). 그래도 슬라이드가 넘어가면 제스처 종료
  후 약 0.25초 시점에 원래 슬라이드로 복귀시키는 가드가 동작합니다 — 단,
  사용자가 직접 클릭해 이동한 경우는 되돌리지 않습니다.
- Ctrl+휠 확대/축소는 커서가 캔버스 가장자리에 아주 가까우면 중심이 안쪽으로
  최대 ~70px 보정될 수 있습니다 (두 손가락이 캔버스 안에 있어야 하므로).
- 터치 주입은 Windows 8 이상이 필요합니다 (Windows 10/11 전부 해당).
  터치 주입을 사용할 수 없는 환경에서는 이동/확대 기능만 자동으로 꺼지고
  걸침 선택은 정상 동작합니다.

## 뷰포트 진단 로그 (자석 밀착 검증)

트레이 메뉴에서 **"뷰포트 진단 로그 기록"**을 켜면 제스처가 진행되는 동안
`%LOCALAPPDATA%\PptFigmaDrag\viewport-log.csv`에 **약 15ms 간격**으로 마우스
커서 좌표와 파워포인트 뷰포트 좌표가 같은 시점에 기록됩니다.

| 컬럼 | 의미 |
|---|---|
| `wall_clock`, `elapsed_ms` | 절대 시각(ms 포함), 로그 시작 후 경과 ms |
| `phase` | `pan`(가운데 드래그) / `wheel` / `pinch` / `idle` |
| `cursor_x_px`, `cursor_y_px` | 마우스 커서 물리 픽셀 좌표 |
| `slide_origin_x_px`, `slide_origin_y_px` | 슬라이드 (0,0)점의 화면 픽셀 좌표 = 뷰포트 위치 |
| `px_per_pt_x/y`, `zoom_percent` | 배율 |
| `cursor_slide_x_pt`, `cursor_slide_y_pt` | **커서가 가리키는 슬라이드 좌표** |

자석 밀착(3번 요구사항) 검증법: 팬 중에는 커서가 가리키는 슬라이드 좌표가
변하지 않아야 하므로, `phase=pan` 구간에서 `cursor_slide_x_pt`,
`cursor_slide_y_pt`가 일정하면 완벽하게 붙어 있는 것입니다. 참고로
DirectManipulation 애니메이션 중에는 파워포인트가 좌표를 늦게 갱신할 수
있어 로그가 계단형으로 보일 수 있습니다(최종 위치 기준으로 판정하세요).

## 걸침 선택의 동작 원리 (요약)

- `WH_MOUSE_LL` 전역 훅으로 왼쪽 버튼 다운/업만 감지 (이벤트를 가로채지 않고 통과만 시킴)
- 버튼 다운 시 워커 스레드가 COM(Late binding)으로 확인:
  - 활성 창이 파워포인트 편집 화면(기본 보기)인지
  - 드래그 시작점이 슬라이드 캔버스의 빈 영역인지 (도형 위·크기조절 핸들 근처·리본·썸네일이면 개입 안 함)
  - 현재 슬라이드의 도형 위치·회전을 스냅샷 (회전된 도형은 AABB로 계산)
- 버튼 업 시: 드래그 사각형을 슬라이드 좌표로 환산 → 걸친 도형들을 `ShapeRange.Select()`
- 좌표 변환은 `PointsToScreenPixelsX/Y`를 매번 새로 샘플링하므로 줌·스크롤·자동
  스크롤에도 정확합니다. Per-Monitor V2 DPI 인식이라 고해상도/다중 모니터에서도 좌표가 맞습니다.

## 개입하지 않는 경우 (안전 장치)

- 도형 위(외곽선 몇 px 여유 포함)에서 시작한 드래그 — 이동/복사와 충돌 방지.
  높이 0인 가로선·세로선, 대각선·직선 연결선(실제 선분 기준)도 잡아냅니다.
- 텍스트 편집 중 자동 맞춤이 꺼져 프레임 밖으로 넘친 텍스트 영역의 드래그
  (실제 텍스트 높이까지 가드 확장)
- 선택된 도형의 핸들 근처에서 시작한 드래그 (크기조절/회전)
- 맞춤 안내선(가이드) 근처에서 시작한 드래그 (가이드 이동과 충돌 방지)
- `Ctrl`/`Alt`를 누른 드래그 (파워포인트 고유 기능 유지)
- 6px 미만의 움직임 (클릭으로 간주)
- 슬라이드 쇼·여러 슬라이드 보기 등 기본 편집 화면이 아닌 경우
- 리본에서 시작한 드래그, 그리고 썸네일·노트 창에서 일어난 드래그
  (버튼을 뗀 시점에 활성 창이 슬라이드 편집 창인지 재확인)
- **도형 그리기·텍스트 상자·잉크 드래그**: 드래그 후 도형 개수가 변했으면
  마퀴가 아니라고 판단하고 개입하지 않습니다.
- 드래그 후 파워포인트가 선택한 도형 중 스냅샷에 없는 도형이 있으면
  (빠른 도형 이동 등) 개입하지 않습니다.
- 내용이 없는 자리표시자("제목을 추가하려면 클릭")는 피그마처럼 마퀴가
  통과하고 선택 대상에서도 제외됩니다. 단, 자리표시자가 **선택된 상태**라면
  이동/크기조절로 판단하고 개입하지 않습니다.

## 알려진 제한

- 드래그 도중 `ESC`로 취소한 경우에도 버튼을 떼면 선택이 적용될 수 있습니다.
- 직선·직선 연결선은 실제 선분 기준으로 정확히 판정하지만, 회전된 도형과
  꺾임/곡선 연결선은 회전 반영 바운딩 박스 기준으로 판정합니다.
- 도형이 수백 개인 슬라이드에서는 버튼을 뗀 뒤 선택 확장까지 0.1~0.5초 정도
  걸릴 수 있습니다(마우스 자체는 밀리지 않음).
- PowerPoint가 DPI 가상화 모드(구형 MSI Office 2016, "호환성에 맞게 최적화"
  설정)로 실행 중이면 좌표를 물리 픽셀로 자동 변환합니다. 변환이 안 되는
  특수한 구성에서는 잘못 선택하는 대신 아무 동작도 하지 않습니다.
